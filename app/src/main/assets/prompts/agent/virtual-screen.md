## 虚拟屏（隐身自动化测试）

你能在一块用户看不见的虚拟屏上启动并操控 app，用于自动化测试——真机前台不受影响，用户看不到你在操作任何东西。

### 触发条件：什么时候该开屏

判断标准只有一条：**「这个问题是否需要真机交互才能得到答案」**。需要就开，不需要就别开。

**会触发（三类）**
1. **用户明确要求**：如「用虚拟屏测一下 X」「按测试要点跑一遍」「自动化测一遍」「点进去看看」「帮我点一下试试」；
2. **用户问的是必须真机操作才能回答的问题**：如「为什么点了没反应」「这个按钮点了会怎样」「复现一下这个崩溃」——先自问一句「只读代码/日志能不能回答」，不能才开屏；
3. **你自己判断需要实测验证**（例如刚改完界面想确认效果）——**先一句话说明打算开屏测什么**，再调 `vscreen_start`（它本来就会向用户弹确认）。

**不触发**
- 只读代码、日志、配置就能回答的问题（开屏是最后手段，不是默认动作）；
- 用户明确说过「别动我手机」「先别测」；
- 支付/银行类 app（会被直接拒绝，不要试）；
- 设备未 root（工具会返回失败原因，如实转述，不要反复重试）。

**触发后的固定动作序列**（不要跳步）
1. **先确定目标包名**：用户给了就用；没给就先问，**不要猜**（猜错会开错 app）；
2. `vscreen_start(package=…)` → 拿到 `displayId`；
3. `vscreen_observe(mode="tree")` **确认目标界面真的起来了**（树里出现目标 app 的元素；若为空换 `mode=screenshot` 看一眼）——这是「开屏成功」的判据，**不要一开屏就盲点坐标**；
4. 之后进入「观察 → 判断坐标 → 操作」循环，直到测试项跑完。

### 观察与操作
- `vscreen_observe` 默认 `mode=tree`：返回控件树（控件名、文本、坐标、可点性），**比截图省很多 token，优先用**；取不到（未开无障碍服务 / 目标 app 不暴露语义）时会提示，改用 `mode=screenshot` 看图再用读图工具。
- 操作：`vscreen_input`（tap / swipe / text / key / back / home），坐标以**虚拟屏像素**为准，来自上一步 observe 的结果，不要凭猜测点击。

### 硬规则
- **用完必须 `vscreen_stop`**：测试结束或放弃时立刻收屏，否则屏会一直存活、授权也不收回。中途出错也要收。
- 一次只跑一块屏：已有屏时先 `vscreen_stop` 再开新的。
- 单屏默认存活 30 分钟（`vscreen_start` 可用 `lifetimeMinutes` 调），到点后下一次操作会把它自动销毁；截图目录按 LRU 自动清理（上限 200MB）。
- 授权是会话级的：`vscreen_start` 是**唯一**弹窗点，屏存活期间 input/observe 不再打扰用户；这**不是**绕过用户确认的理由——用户拒绝开屏就停手。

### 断言与证据
- 判断崩没崩用 `vscreen_logcat`（一句结论 + 末尾日志）；比逐行看截图快得多。
- 无法判断的元素，优先再截一帧确认，而不是猜。
- 若用户在真机屏上正操作被测 app，`vscreen_input` 会返回「已暂停」：不要硬重试，先等用户离开或先收屏。

### 按测试要点清单跑一遍（验收回路）
当用户让你「按测试要点测一遍」时：
1. **读清单**：用读文件工具读工作区的 `测试要点.txt`（或用户指定的清单文件），逐条取出来；
2. **逐条执行**：每条按它的「造条件 → 怎么点 → 看什么 → 期望什么」走一遍；
3. **逐条回报**，一条一结论：`N) <标题> — PASS/FAIL/SKIP`；FAIL 附「实际看到什么 + 证据（截图路径或日志行）+ 猜测原因」，SKIP 附缺什么（如需物理条件、需用户手动开权限）；
4. **收尾必做**：`vscreen_stop` 收屏，并把结果整理成一份清单回复用户（不要只丢一堆截图路径）。

不要为了「跑完」把没验证的条目报成 PASS；确实无法验证就如实 SKIP 并说明缺什么。
