# 记忆与项目规则

本章介绍自动记忆与项目规则两项能力，用于保持 AI 跨会话的上下文连续性与项目一致性。

## 自动记忆

自动记忆是 AI 自行维护的**长期**知识库（跨会话存活）。对话中形成的项目约定、用户偏好与架构决策，AI 会自动记录并在后续会话中复用。

与它相对的是**短期**内容：本次会话的对话历史与折叠摘要，只活在这一次会话里。设置页把两层分开：记忆页顶部会显示一张只读的「本次会话（短期）」卡片，下面是长期记忆清单。

记忆有两条写入路径：

- **对话中主动记**：打开「长期记忆自动沉淀」开关后，AI 每轮收尾前会判断这一轮是否出现了关于你的稳定结论（偏好与表达习惯、对你做法的纠正、环境或工具限制、项目约定等），有就调用记忆工具写下来。你在「设置 → 记忆」里能立刻看到，也能自己改或删；
- **周期治理**：到治理周期后，系统对已有记忆做一次收敛（去重、合并、清理），见下面的[记忆治理](#记忆治理)。

另外，长对话触发上下文折叠时，系统会先从即将离开窗口的那段历史里捞一遍值得长期保留的结论写进记忆——那段内容马上就不在上下文里了，不捞就永久丢掉。

### 作用域

| 作用域 | 说明 | 存储位置 |
| --- | --- | --- |
| 全局 | 跨项目通用的个人偏好 | `~/.aicode/memory/` |
| 项目 | 当前项目专属的约定与经验 | 本地模式：`<项目根>/.aicode/memory/`；远程 SSH 模式：`~/.aicode/memory/projects/<项目名>-<标识哈希>/` |

项目记忆在远程模式下存储于手机本地，并按「项目名 + 服务器标识」隔离，不受容器重置影响。

### 记忆文件

每条记忆是一个 Markdown 文件，由 YAML frontmatter（`name`、`description`）与正文组成：

```markdown
---
name: conventions
description: 项目代码规范与命名约定
---
（正文）
```

frontmatter 里还可能出现 `kind`、`source`、`created_at`、`hit_count`、`last_hit_at` 这类由 App 维护的元信息（类型、来源、创建时间与命中统计），手写时可以省略。覆盖、编辑或删除一条记忆时，旧版本会先归档到记忆目录下的 `.superseded/`，改错删错还能从那里找回。

### 生效方式

AI 每轮看到的不是全部记忆，而是按当前话题挑出来的一份清单：

- 按与当前话题的文本相关度排序，最多注入 5 条；前 3 条无条件保留，之后只在描述总长还有预算时才继续放——吃窗口的是描述长度，不是条数；
- 没被展开的条目会以名字列在清单末尾，AI 需要细节时用 `memory` 工具读取完整正文；
- 被注入过的条目会累计命中次数；创建超过 30 天且从未命中过的条目，排序时会被降权（仍然保留，只是相关度接近时排在更新鲜的条目后面）。

AI 写入或删除记忆后，下一轮请求就会带上新清单，不需要重开会话。

### 声称记住了、其实没调用工具

如果 AI 在回复里写了「我记住了」，而这一轮它并没有真的调用记忆工具，系统会补一条提醒让它当场补调用。你看到的现象是：这类回复之后可能紧接着一次很短的工具调用。只在命中时才多这一次往返，正常讨论记忆功能的对话不受影响；前提是上面的自动沉淀开关开着，开关关着时连规则都没注入，不做这层兜底。

### memory 工具

| 参数 | 说明 |
| --- | --- |
| `action` | `read` / `save` / `edit` / `delete` / `list` |
| `name` | 记忆名称（即文件名） |
| `description` | 摘要，`save` 时必填 |
| `content` | 正文（Markdown），`save` 时必填 |
| `edits` | 局部编辑列表，语义与编辑文件一致 |
| `scope` | `project`（默认）或 `global` |

同名记忆项目级优先于全局。写入全局作用域时如果当前项目已有同名条目，工具会明确告诉 AI 这一点（项目级会把全局那条遮蔽掉，否则它会以为自己刚写的生效了）。更新既有记忆时建议使用 `edit` 局部编辑；涉及踩坑经验的内容，应在验证根因后记录。

### 记忆治理

记忆治理是把「越来越多、越来越脏」的记忆定期收敛一次。它只处理已有条目，不新写内容，分两层，先便宜后聪明：

1. **本地规则（不调用模型）**：空壳条目（没有描述或正文）、近似的重复条目直接归档；记忆条数不多时，创建超过 30 天且从未被命中过的条目也按死条目归档；
2. **一次小调用**：条目足够多（6 条及以上）时，再把每条的名称与描述发给模型，让它指出「哪几条说的是同一件事」与「哪几条该退场」。**正文不上传**，只有需要合并时才在本地读。

门槛与节奏：少于 4 条记忆不做治理；治理在每轮对话结束时检查一次，距上次治理已经超过设定周期才真正跑，而且同一时刻只会跑一次——多个会话同时结束一轮也不会重复治理、重复调模型。

治理结果不静默丢东西：合并是把其它条目的正文并进保留的那一条（近重复的段落不会重复拼接）；退场是把文件移进 `.superseded/` 留底。

### 在设置页管理记忆

进入「设置 → 记忆」，顶部是设置项与一张只读的**「本次会话（短期）」**卡片（显示本次会话的上下文占用与折叠摘要状态，没有会话数据时不显示），再往下是当前生效的**长期记忆**清单：

| 设置 | 说明 |
| --- | --- |
| 主动记忆 | 打开后 AI 才会在对话中主动记，并在它声称「记住了」却没调用工具时补一条兜底提醒。默认关闭 |
| 记忆治理 | 是否按周期收敛已有记忆。默认关闭 |
| 治理周期 | 可选关闭 / 1 天 / 7 天 / 自定义，默认 1 天。周期选「关闭」即等于关掉治理开关 |

> 压缩前抽取记忆不受这两个开关影响：长对话折叠时从即将离开窗口的历史里抢救结论，是无条件的。

清单里的操作：

| 操作 | 效果 |
| --- | --- |
| 点击某条 | 查看完整正文与来源 |
| 长按某条 | 弹出「编辑 / 删除」 |
| 左滑某条 | 露出删除按钮 |
| 右上角「+」 | 新建一条记忆 |

点右上角「+」或长按某条，进入**全屏编辑页**（不是弹层）：名称、描述、正文、作用域分块排列，正文输入框给足高度。名称与描述会注入提示词，正文平时不展示。新建时可以选作用域（全局 / 项目）；编辑已有记忆时名称只读（它是记忆的唯一标识），作用域沿用原条目。保存后立即生效，无需重启。删除失败时（比如该条目已经不存在）会给出一次提示，而不是让条目留在列表里不说原因。

## 项目规则

项目根目录下的 `AGENTS.md` 用于声明项目专属规则、架构约束与构建指南，是 AI 遵循的最高优先级约定；不存在 `AGENTS.md` 时回退读取 `CLAUDE.md`。

### 生效方式

规则文件在会话开始时自动加载，无需手动配置；内容超过 32,000 字符时将被截断。

### 自定义加载约定

项目规则的加载约定对应提示词片段 `15-project-rules.md`，可通过 `~/.aicode/prompts.custom/15-project-rules.md` 覆盖，见[自定义提示词](/guide/custom-prompts)。
