# 备份与还原

「设置 → 备份与还原」可以把应用配置、聊天历史、工作区文件导出成一个压缩包；需要迁移登录凭据时，再额外勾选「凭据」并设置口令。也能从备份还原回来。

## 导出

页面上方按「数据 / 配置 / 凭据」三组勾选导出范围，勾选状态会记住，下次进来沿用：

- **数据**：聊天（点这一行打开二级面板，可单独选择长期记忆、会话工作状态）、工作区文件、技能与子代理、面板脚本。
- **配置**：AI 供应商、连接与同步、MCP 服务器、授权规则、应用设置。
- **凭据**：git 令牌、SSH 私钥与登录口令、网络备份目标密钥、MCP 授权令牌、AI 供应商 API Key 与代理密码、连接密码。默认关闭。

「AI 供应商」与「连接与同步」只导出配置本身——供应商名称、类型、Base URL、模型列表，连接的地址、端口、用户名、认证方式与挂载点；API Key、代理密码、连接密码这些能直接用于登录或计费的值不在其中，只有勾选「凭据」才会随包导出。**不勾「凭据」时，包里不含任何密钥**，普通数据照常明文导出。

「应用设置」里包含当前的**执行模式**（本地 / 远程 SSH）：勾上它导出的备份，导入到另一台设备后会连同模式一起还原。

**技能与子代理**默认打开：打包全局（`~/.aicode/skills`、`~/.aicode/agents`）与当前工作区（`.aicode/skills`、`.aicode/agents`）两级的目录，外加两级的启停配置（`skills.json` / `agents.json`）。目录按文件逐个打包，技能里附带的脚本、附件这类非文本文件一并带走。**面板脚本**默认打开，打包面板脚本目录（`~/.aicode/scripts`）。这两项与聊天、工作区文件一起归在「数据」组，页面上可以分别关掉。这几类都跟随当前执行环境：本地模式读写 App 私有目录，远程模式读写服务器 home 下的 `.aicode`，因此远程模式导出的是远端那一份。

其中**工作区文件默认关闭**，需要时手动打开。它会打包所有本地模式的内部工作区文件，包含 `.git` 目录，因此仓库历史和未推送的提交也能还原；Git 配置和钩子有单独的安全跳过规则（见下文）。通过「添加外部工作区」加进来的外部工作区属于你设备上的原始目录，不会被打包。排除规则是各工作区自己的 `.gitignore` 加上同步功能的默认忽略清单（`node_modules`、`build`、`dist` 等），符号链接不备份。

### 工作区文件能导出多少：看导出完成后的摘要

工作区文件不会因为某个工作区读不到就整包失败——**能拿到的部分照样导出**，导不进去的部分在完成提示里逐条列出来：

- 第一行：这次实际写入了多少个工作区文件、来自几个工作区。
- 第二行：跳过了几个工作区，括号里写原因，例如「远程未连接，读不到文件」「宿主目录不存在」「没有文件」。工作区太多时只列前几个，超过的部分折叠成「…等 M 个」，M 是跳过的总数。

::: warning 远程模式下的导出限制
「工作区文件」段只处理**本地磁盘上的内部工作区**，远程工作区（文件在服务器上）不参与导出，这不是出错，而是当前版本的已知限制：

- 远程模式下工作区列表里只有远程工作区，它们全部会被跳过，摘要里会写明「跳过的工作区 M 个（远程……）」。
- 如果这次一个工作区文件都没导出、而你又处于远程模式（或列表里有远程工作区），摘要会明确写一行：**远程工作区文件未包含：需要在远程模式下连接后导出**。注意连接只是前提，当前版本不会导出远程文件；要备份服务器上的代码，请用服务器上的 Git 仓库。
- 想备份本地内部工作区的文件，请切回本地模式（或确保这些工作区出现在列表里）再导一次。
- 远程未连接时，连工作区列表都读不出来，导出照样能完成，但摘要里不会有具体的工作区名——先连上再导出才能看到明细。
:::

::: tip 代码优先用 Git 备份
Git 仓库本身就完整保存了代码和历史，这里的导出更适合作为额外的备用手段，而不是主要的代码备份方式。
:::

点「导出备份」后会弹窗设置口令：

- **填写口令**：使用 AES-GCM 加密。
- **留空**：输出明文 tar.gz。不勾「凭据」时可以这样导出，包内不含任何密钥。
- 勾了「凭据」时必须填写口令，留空无法导出——凭据不会退化成不加密，也不会悄悄省略。

导出的包通过系统文件选择器保存到你指定的位置。

::: danger 务必牢记加密口令
加密备份在遗失口令时无法解密恢复，没有任何后门或找回途径。
:::

## 导入

从备份文件还原，采用**合并方式**，不会清除现有数据。需要输入对应的口令，未加密的备份留空即可。

只有导出时勾选了「应用设置」的备份才会恢复主题、配色和偏好设置。单独导出的聊天记录，以及未勾选「应用设置」的备份，导入后会保留当前应用设置。

**执行模式也会随备份一起恢复**：备份是在远程模式下导出的，导入后应用会回到远程模式；备份是在本地模式下导出的，导入后仍留在本地模式。切回远程模式后如果还没连上服务器，到「远程 SSH」页面连接一次即可。

远程会话的聊天记录**只在远程模式下可见**：它们属于服务器上的工作区，本地模式下聊天列表里看不到，这不代表数据没恢复。想看它们要同时满足两件事——应用处于远程模式，并且已经连上服务器。

加密备份在预览前会完整解密并校验一次，确认恢复时复用校验结果，不再重复解密。较大的备份需要足够的应用内部存储空间保存临时压缩包；完成、取消或失败后会清理临时文件。

导入前会先校验备份格式：文件必须是本应用导出的包。格式不完整（缺少元数据段、或包已损坏）时直接报错，**不会先写一半数据再失败**，本机现有内容保持不变。

如果备份中含工作区文件，会先弹出「恢复工作区」选择弹窗，列出备份中的每个工作区（名称和文件数），你可以勾选要恢复哪些。

::: warning 恢复工作区会直接覆盖
勾选的工作区会覆盖本地同名工作区里的文件，且无法撤销。本地没有同名工作区时会自动新建一个再写入，因此更换设备或重装后不会丢数据。远程模式的工作区（文件在服务器上）不参与还原。
:::

为避免备份中的 Git 配置或钩子在本机执行命令，还原工作区时会跳过根目录及嵌套仓库的 `.git/config` 和 `.git/hooks` 下的文件，包括带有 `.`、`..` 的等价路径，以及本机已有符号链接映射到这些位置或从这些位置映出的文件。越出工作区的路径也不会写入。已有的配置和钩子保持不变，备份里的这些文件不会新建；`.git/objects`、`.git/refs` 等历史数据和普通工作区文件仍可还原。需要迁移 Git 配置或钩子时，请先检查内容，再手动配置。

导入完成后会显示还原数据的汇总清单：供应商、Git 凭据、远程连接、远程挂载、聊天会话、聊天消息、待办项、MCP 服务器、全局授权规则、工作区文件、技能文件、子代理文件、面板脚本各恢复了多少；启停配置真的回写了两级配置文件时，还会多一行「技能与子代理的启停状态已覆盖」。安全跳过的 Git 文件会单独计数，不计入已恢复的工作区文件数。备份里带了远程连接/远程挂载、或者本次把执行模式切回了远程时，摘要末尾还会多一句提醒：远程聊天记录只在远程模式下显示，连上 SSH 后才能看到。勾选「凭据」导出的包，供应商密钥与连接密码会按条计入「凭据 N 项」这一行；旧版本导出的包把密钥写在配置段里，仍按原逻辑恢复，但不计入这一行。

**没落盘的工作区文件也会单独计数**：某个工作区文件在备份里有、但本机找不到可写入的目标（典型情形是远程模式下还没连上服务器，或目标工作区目录已被删除）时，这些文件会被跳过，摘要里会多一行「跳过的工作区文件 N 个（目标工作区不可用，如远程未连接）」。见到这一行时，先连上远程（或确认工作区目录还在），再用同一份备份重新导入一次即可补齐——导入是合并写，重复导入不会产生重复记录。你在勾选弹窗里主动取消的工作区不算跳过，它们只是按你的选择不恢复。

技能、子代理与面板脚本按备份里的文件**覆盖同名文件**，本机多出来的技能不会被删——导入之后本机是并集，而不是备份那一刻的快照。项目级（工作区 `.aicode/` 下的技能与子代理）落到**导入时的当前工作区**：容器里只有当前工作区被映射进来，所以导出时哪个工作区在生效，带的就是那个工作区的项目级资产；换工作区导入时想让它归位，先切到目标工作区再导入。启停配置是整份覆盖（备份里的名单为准），所以导入设备上「本机额外禁用、备份里没有」的技能会重新启用；没勾「技能与子代理」导出的备份则完全不碰本机的启停配置。

聊天会话会按备份时的所属工作区归位：本地有同名工作区直接还原过去，没有同名工作区时会自动新建一个空工作区再挂入会话（与「恢复工作区」自动新建的逻辑一致），更换设备或重装后各工作区的会话不会集中到同一处。

导出时没勾「应用设置」的那份备份里不带设置段，导入它只还原它确实包含的数据，不会把你当前的设置重置成默认值——保活、屏幕常亮、提示音、超时与压缩阈值都保持原样（单会话备份同理，它本来就不带设置）；备份带了设置段时照旧覆盖，导入摘要里也会写明「主题、保活、日志、识图、同步偏好已覆盖」。

## 网络备份

除了导出成本地文件，还可以把备份直接上传到云端，或从云端拉回还原。备份页底部有「本地备份 / 网络备份」两个标签：本地页管导出范围与导出/导入，网络页管备份目标。切到「网络备份」后用右上角「＋」添加**备份目标**，支持两类：

- **WebDAV**：填服务器地址（含路径，如 `https://dav.jianguoyun.com/dav`）、远端目录、用户名和密码。
- **对象存储 (S3)**：填服务地址、区域、存储桶、Access Key / Secret Key，可加 Session Token 与对象前缀，路径风格寻址可切换。兼容 AWS S3、Cloudflare R2、阿里云 OSS、腾讯云 COS、MinIO 等 S3 兼容服务。

每个目标都能「测试连接」验证配置。配置好后：

- **上传到云端**：导出当前勾选的备份并上传到所选目标；必须设置口令加密，不能上传明文。上传完成后弹出的摘要与本地导出同一套：工作区文件实际写了多少、哪些工作区被跳过，都会列出来。
- **从云端恢复**：列出所选目标上的备份（按时间倒序），选一个下载并还原，流程与从本地文件导入一致（含口令校验与工作区勾选）。

每个目标卡片底部都有「上传」「恢复」按钮；点卡片进入编辑，左滑删除。

远端文件名形如 `aicode-backup-<时间戳>.tar.gz`。备份目标里的密码与密钥由系统密钥库（Android Keystore）加密保存，与备份本身的加密口令相互独立。

::: warning 云端备份同样可能含凭据
勾选了「凭据」的备份包含 API Key、SSH 口令等敏感值，上传到云端时必须设置口令加密。不勾「凭据」的包不含密钥，但仍可能包含聊天记录与工作区文件。
:::

## 补充说明

备份口令只作用于导出的备份文件本身。应用内部存储的 API Key、连接密码、SSH 私钥等敏感配置另由系统密钥库（Android Keystore）加密保存，与备份口令相互独立；更换设备时请通过备份导入迁移，直接拷贝应用数据目录会因密钥不匹配而无法解密。
