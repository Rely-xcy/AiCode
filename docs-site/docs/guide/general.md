# 偏好设置

「设置 → 通用设置 → 偏好设置」收纳了不针对具体供应商、也不属于特定用途的全局偏好开关。改动即时生效，无需保存。

## 模型

**拉取模型后自动移除无效模型**（默认开启）

开启时：在[供应商编辑页](/guide/providers)点「拉取模型」，只要服务端成功返回模型列表，本地列表里那些服务端已不再返回的模型就会被自动移除，并弹出提示告知移除了几个。

- 请求失败或服务端返回空列表时不会动本地列表，避免网络异常将已添加的模型清空。
- 手动添加的模型如果恰好不在服务端返回结果里，也会被一并移除。介意这一点可以关掉开关。
- 关掉后，拉取只负责把新模型列出来供你勾选，不再改动已有列表。

**自动压缩阈值**（默认 85%，可填 1-100 的整数）

上下文用到模型窗口的这个比例时，自动触发上下文压缩（把早期对话摘要成接手摘要）。调大则更晚压缩、更贴近窗口上限；调小则更早压缩、但摘要更频繁。

实际触发线还可能被**窗口档位上限**压低（给输出和提示词留 headroom）：比如 128K 窗口的档位上限是 108K，85% 算出来是 108.8K，实际按 108K 触发；1M 窗口的档位上限是 980K，85% 的 850K 没碰到上限，就按 850K 触发。设置页会把这条线直接写出来：「实际 85%（850,000 tokens）」；真的被上限压低时才加一句说明：「实际 84%（108,000 tokens，受档位上限限制）」——百分比与 token 数按**默认模型**的窗口算，与你填的百分比一起看，就不会出现「填了 85% 却不知道实际按多少跑」。窗口不足 64K 的档位不做自动压缩，只做软精简（这两行会直接说明）。

压缩完成后如果仍逼近窗口，还有一道 92% 的兜底：对单条过长的消息本身做硬截断。三道线（软精简 / 自动压缩 / 兜底截断）用的是同一套 token 数，聊天页输入框旁的圆环显示的也是这套数，不会出现「显示还没到线、压缩却已经触发」。

折叠腾出的空间也可能当场被吃掉——保留的最近原文本身就很长时，折完依旧在硬线以上。这种情况不会再在同一轮或紧接着的几轮反复折（可折的早期对话已经折完了，再折只会得到同一份摘要）；聊天里会出现一条「上下文压缩提示」说明当时两个数，后续交给 92% 兜底截断保底，不会把超窗请求发出去。摘要模型本身报错时同理：失败只上报一次、不会每轮重试，也不会因此停掉软精简、自动压缩与兜底截断这三道线中的任何一道。

**软精简阈值**（默认 40%，可填 1-100 的整数）

上下文**略微超过**这个比例时才动手（刚好到这个数不会触发，避免每轮都重算一遍），做一轮**不调用模型**的瘦身：历史里超长的工具输出被首尾保留、中间截断；写入、编辑类工具调用携带的大块文件正文被换成一段**摘录**——开头与结尾逐字保留、中间一行写明省略了多少行/字符，并给出回读路径，文件已经在磁盘上，AI 需要全文时按提示读回即可。极短的文本实在省不下内容时，则退回一句占位说明。无论哪种形态都不是真正的文件内容，AI 把它们当正文回写会被执行边界直接拦下并提示先读回全文。

这一步只改「发给模型的那一份」：聊天记录里的工具卡片、工作区文件都不受影响，事后翻记录看到的仍是完整内容。精简到够用就停，不会每轮重跑；软线始终被压在自动压缩线之下，所以就算把它填得比自动压缩阈值还大，也不会抢在硬压缩前面触发。

真的触发自动压缩（做摘要）时，同样的精简会先跑一轮，作为压缩前的兜底。

## 会话

**启动时会话**（默认「新开会话」）

- **新开会话**：每次打开 App 都从新会话开始。当前工作区如果还留着一个没发过消息的空会话，会直接复用，不会再新建一个。
- **打开最近会话**：直接进入当前工作区里最近更新的那个会话，接着上次继续。该工作区还没有任何会话时会新建一个。置顶会话不会优先——即使有置顶会话，也仍进入最近更新的那个。

切换工作区时也按同一个偏好处理。

**删除外部工作区聊天记录**（默认关闭）

控制移除「添加本地目录」加进来的外部本地工作区时，聊天记录如何处理。开启后，移除外部本地工作区会一并删除它的会话与消息；关闭则只解除关联、保留聊天记录，之后重新添加同一目录仍可看到历史。

应用内置工作区与远程工作区的删除不受该开关影响：删掉它们时，目录与聊天记录都会一并删除。

## 输入

**回车键发送消息**（默认关闭）

开启后软键盘的回车键变成发送键，按一下即发出；关闭时回车是换行，由发送按钮发出。多行输入时建议保持关闭。

## 网络

两个超时都以秒为单位，在输入框里填数字即可，**填 0 表示不限制**；保存后对之后的请求立即生效，无需重启。

**首字超时**（默认 300 秒）

每次请求尝试开始后，等待首个有效内容（正文、思考或工具调用）的最长时间，包含等待服务端响应头的时间。超过即取消本次请求，并按重试次数设置重新尝试；每次重试重新计时。慢启动、长思考的模型可以调大。收到首个有效内容后，此超时不再限制后续回复时长。

**数据块间隔超时**（默认不限制）

流式回复过程中，相邻两个响应块之间允许的最长等待。设成具体值后，卡住的连接会更早被断开并重试；网络稳定时保持不限制即可。

**重试次数**（默认 6）

应用会定期探测 HTTP/2 连接，发现连接失去响应时断开并按重试设置处理；HTTP/1.1 连接不支持此探测。界面显示「正在重试」时，可能正在等待退避，也可能已发出下一次请求、正在等待内容。

网络请求失败后的指数退避重试次数（不含首次请求，等待从 0.5 秒起步、按 2 倍递增、单次最长 10 秒）。同一次请求即使已输出部分内容后再次断线，网络重试次数也会累计，不会重新计数。填 0 表示失败直接报错、不重试；同时受多 Key 自动切换影响——被归为 Key 失效的失败会先尝试换 Key 重发。

## 工具

**sendFile 单文件上限**（默认 100MB，可填大于 0 的整数）

AI 用 `sendFile` 把文件发到聊天区时，单个文件允许的最大体积。超过上限的文件不会被发送，AI 会收到失败原因。调大可以发更大的文件，但单个文件会先拷贝到应用私有目录再展示，过大可能占用较多存储。
